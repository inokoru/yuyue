# 语阅 · 广播剧技术方案

> 日期：2026-11-12 ｜ 状态：做法定了，等第 0 步实测 ｜ 这份写给动手实现的人看：模块、数据、算法、参数、验收线都在这里。界面另出原型，原型确认前不写界面代码。
> 从需求重新想的，不沿用以前的方案。

导入一本小说，自动分出角色、给每个角色配不同的声音，旁白照念，加上环境音，听起来像一部剧。

---

## 〇、给实现者

1. **核心不联网、不跑模型**。`core/yuyue-core`（Rust，经 uniffi 给三端）只做纯计算：拆文字、出请求、校验回答、求解、存取。大模型、声音合成、听写、声纹这些都由各端执行，把结果交回核心。这样三端结果一样，核心能在 `cargo test` 里全量测试。
2. **先读再写**。核心里已有用途相近的文件：`script.rs`（拆台词、规则认人）、`roles.rs`（人物和声音设置）、`segment.rs`（分句）、`store.rs`（SQLite）、`podcast.rs`（另一处调大模型的写法）。能接着用的接着用；本文的类型名、函数名是建议，和现有代码风格冲突时以现有风格为准，但**数据的含义和验收线不能改**。
3. **顺序**：先做第十节的考卷和打分，再做功能。没有打分的功能不合并。
4. **每一步的产物带版本**（规则版本、提示词版本、模型名、书的文字摘要）。任何一个变了，只重做受影响的那一层，上层尽量复用。
5. **用户改的永远最大**，任何重算都不覆盖。
6. 本文里的阈值（0.3 秒、97% 这类）是起点，写成常量集中放一处，第 0 步实测后调；调了要在这里改数。

## 一、“准确率 100%”怎么兑现

**全自动 100% 做不到，谁家都做不到。** 英文小说上公开的最好成绩大约是 94–95%（PDNC 语料，22 本小说、三万五千句台词），而且那是把写明的和没写明的合在一起算的；没写明说话人的句子更低。两个人各标一遍也有对不上的句子。

所以目标是下面三条，全部用考卷量（第十节）：

| 目标 | 线 |
|---|---|
| **听到的错是 0**：自动配了人的台词里，配错的 | ≤ 0.1%；书上写明的 0 句 |
| **自动配到人的比例** | ≥ 97%（接了大模型时） |
| **点几下到真 100%**：三十万字的书清完“没把握”清单 | ≤ 60 下、5 分钟内 |

手段只有一个原则：**宁可不认，不要认错**。没把握的台词用一个中性的“对话声音”念，听的人听到的是“这句没分角色”，不是“这句成了别人说的”。

## 二、整体

```
小说文字（核心已有：章 → 句）
  │ ① spans    句 → 段（旁白 / 台词 / 心里话 / 引文）
  │ ② cast     通读全书 → 人物表
  │ ③ scenes   章 → 场（地点、时间、在场的人）
  │ ④ attribute 每句台词：谁说、对谁说、依据、把握
  │ ⑤ direct   每段怎么念；每场什么环境、什么动静；读音表
  ▼
剧本 Script（核心存，带版本，同步）
  │ ⑥ casting  人物 → 声音
  │ ⑦ synth    段 → 人声片段（各端合成，核心管队列、缓存键、质检结论）
  │ ⑧ sound    场 → 环境底、点状音效、过门
  │ ⑨ timeline 片段 → 时间线
  │ ⑩ mix      时间线 → 耳朵（共用的 Rust 混音器）
```

### 2.2 核心和各端怎么说话：作业制

核心是一个状态机，各端是执行者。两个调用就够：

```rust
/// 取下一件要各端做的事；没有就返回 None。可并发取多件。
fn drama_next_task(book_id: String, focus: Loc) -> Option<Task>;
/// 交回结果。核心校验、落库、推进状态；返回这一步之后界面该刷新什么。
fn drama_submit(task_id: String, result: TaskResult) -> Result<Progress>;

enum Task {
    Llm   { id, tier: Tier, system: String, user: String, schema: String /*JSON Schema*/,
            cache_prefix_len: u32, max_output_tokens: u32 },
    Tts   { id, voice: VoiceRef, text: String, act: Act, context: Vec<ContextLine>, cache_key: String },
    Check { id, audio: String /*path*/, expect_text: String, expect_voice: VoiceRef },  // 回听
    DesignVoice { id, description: String, sample_text: String },
    Sfx   { id, description: String, seconds: f32, cache_key: String },
}
enum Tier { Strong, Fast, Verify }   // 各端映射到用户接的具体模型
```

- `focus` 是用户正在读 / 听的位置；核心据此排优先级（2.3）。
- 任务**幂等**：同一个 `id` 交两次，第二次忽略。各端崩了重启，重新 `next_task` 就接上。
- 大模型请求里 `cache_prefix_len` 标出可缓存的固定开头（人物表、说明），各端按服务商的缓存接口用。
- 各端没有某种能力（没接大模型、声音不会演）时，在 `drama_capabilities(Caps)` 里告诉核心，核心就不出这类任务，走降级路线（各节有写）。

### 2.3 先后和进度

优先级从高到低：

1. `focus` 所在章的 ①③ 和规则认人（毫秒级，同步做）；
2. `focus` 所在章的大模型认人 → 导演稿 → 合成当前场和下一场；
3. 通读全书出人物表（一次大请求，后台）；
4. 其余各章按顺序认人；
5. 其余各章合成（只在用户开了“提前做好整本”或设备空闲充电时）。

**不等整本**：1、2 做完就能听（目标 ≤ 1 分钟）。这时还没有全书人物表，用“本章 + 前两章”里规则收到的名字当临时人物表。全书人物表到了之后**对账**：临时人物并进正式人物（按名字集合有交集），已经配出去的声音跟着人物走、不换。

## 三、数据

### 3.1 位置

```rust
struct Loc  { section: u32, sentence: u32 }                 // 沿用核心现有的章、句编号
struct Span { loc: Loc, start: u32, end: u32 }              // 句内字符区间，按 Unicode 标量计，不按字节
```

用户改的记录按 `Loc + 这段开头 12 个字` 存；书的文字变了，先按 `Loc` 找，开头对不上再在前后 20 句里按开头找，找不到就挂起（人物页提示“有 N 处改过的对不上了”），不硬套。

### 3.2 剧本

```rust
enum SegKind { Narration, Speech, Thought, Quoted /*书信、诗、告示、引用的话*/ }

struct Segment {
    span: Span,
    kind: SegKind,
    utterance: u32,          // 同一句台词跨几段、几句时编号相同
    speaker: Speaker,        // 只对 Speech / Thought 有意义
    addressee: Option<CharId>,
    basis: Basis,            // Explicit | Inferred | Content | None
    decided_by: DecidedBy,   // User | Rule | Model | Unsure
    p_correct: f32,          // 校准后的把握；User、Rule 为 1.0
    evidence: Option<Span>,  // 依据所在的原文
    act: Act,
}
enum Speaker { Char(CharId), Group(GroupId), Unsure { top: Vec<(CharId, f32)> } }

struct Act {                 // 导演标注
    emotion: Emotion,        // Neutral, Joy, Anger, Sadness, Fear, Surprise, Disgust, Tender, Mocking, Anxious, Weary
    level: u8,               // 0 平 / 1 轻 / 2 中 / 3 重
    volume: Volume,          // Whisper, Low, Normal, Loud, Shout
    pace: Pace,              // Slow, Normal, Fast
    nonverbal: Vec<Nonverbal>, // Laugh, Sigh, Sob, Gasp, Cough —— 在段首还是段尾
    distance: Distance,      // Close, Normal, Far, Offstage（门外、隔墙）
    from_text: bool,         // true = 原文写了的；false = 模型推的
}

struct Character {
    id: CharId,
    names: Vec<Name>,        // { text, kind: Full|Short|Courtesy|Nickname|Title, from_section, to_section }
    called_by: Vec<(CharId, String)>,   // 谁嘴里的什么称呼：(贾宝玉, "老祖宗") → 贾母
    gender: Gender,          // M | F | Unknown
    age: Age,                // Child | Teen | Young | Middle | Old | Unknown
    traits: String,          // 一句话：身份、性格、说话的样子
    first_speaks: Loc,
    revealed_same_as: Option<(CharId, u32 /*从第几章起读者才知道*/)>,
    evidence: Vec<Span>,
    lines: u32,
    provisional: bool,       // 全书人物表到之前的临时人物
}

struct Scene {
    id: SceneId, section: u32, first: u32, last: u32,     // 句号闭区间
    place: String, place_kind: PlaceKind,                 // 见 8.1 的清单
    indoor: bool, time: TimeOfDay, weather: Weather, crowd: Crowd,
    present: Vec<(CharId, u32 /*进场句*/, Option<u32> /*离场句*/)>,
    events: Vec<SoundEvent>,                              // 见 8.2
}
```

### 3.3 存

SQLite（和书库同一个库，或每本书一个附属库，照 `store.rs` 现有做法）：

| 表 | 主键 | 内容 | 同步 |
|---|---|---|---|
| `drama_spans` | book, section | 这一章的 Segment 列表（规则部分），压缩 JSON；规则版本 | 否（各端自己算，结果一样） |
| `drama_cast` | book | 人物表；提示词版本、模型名 | 是 |
| `drama_scenes` | book, section | 场、场景单 | 是 |
| `drama_model` | book, section | 模型给的认人结果、导演稿（只存和规则不同或规则没有的） | 是 |
| `drama_user` | book, anchor | 用户改的：说话人、合并、拆分、改名、读音 | 是 |
| `drama_voices` | book, char | 选角结果、每人的快慢高低 | 是 |
| `drama_clips` | cache_key | 合成好的片段：文件、时长、质检结论、字级时间（有的话） | 否（音频可走局域网传） |
| `drama_tasks` | id | 作业状态：待做 / 做着 / 做完 / 失败次数 | 否 |

读的时候按 `用户 > 规则 > 模型 > 没把握` 合成一份 `Script` 给上层；播放器、人物页、气泡都只读这一份。

## 四、① 拆段 `spans.rs`

输入一章的句子，输出 `Vec<Segment>`（这时 speaker 未定）。纯规则，要快：整本《红楼梦》≤ 2 秒。

**引号对**：`“ ”`、`‘ ’`、`「 」`、`『 』`、`« »`、直引号 `"`（按开合交替配对；英文单词内的 `'` 不算引号：两侧都是字母）。用栈处理嵌套，只有最外层算一段台词。

**跨句、跨段**：一句里开了引号没收，往后找收引号（最多 40 句；超了当作排版错误，这一句的引号作废、记日志）。一段结尾没收引号、下一段开头又开引号（英文小说的长台词写法），算同一个 `utterance`。

**不算台词的引号内容**（记 Narration 或 Quoted）：

- 引号里 ≤ 4 个字且没有句末标点，且引号前后紧挨着的不是说话词 → 强调或引词，Narration；
- 引号前 6 个字内有“写着、题着、刻着、上书、名曰、叫做、所谓、称为”等 → Quoted；
- 书名号里的；
- 引号前是“心想、暗道、寻思、自忖、thought、wondered”等 → Thought。

**没有引号的书**：一章里引号内的字 < 2%、而“道：”“说：”“——”开头的行 ≥ 5 处，判为“无引号体”。接了大模型时出一个 `Tier::Fast` 任务：给这一章带句号的原文，要它回每句里台词的起止字符位置；核心校验区间落在句内、不重叠，校验不过的那句整句当旁白。没接大模型：只认两种确定的写法——行首 `——` 到行尾、行首 `名字：` 到行尾。

**替换规则**（用户设的读音替换）在拆段之后、合成之前应用，段的边界不动。

测试：`fixtures/drama/spans/` 放各种写法的小样，每个写法至少正反各三例。

## 五、② 人物表 `cast.rs`

### 5.1 规则收名字（没接大模型也有）

从说话词前后收：`X道 / X说 / X笑道 / X问 / X答…`、`said X / X said / X replied…`。说话词表放数据文件（中文约 200 个、英文约 80 个），不写死在代码里。只做确凿的合并：全名包含短名且短名在书里不指别人（贾宝玉 = 宝玉；书里有甄宝玉则不合）；只差“儿”“子”“老”“小”这类词缀的不自动合。

### 5.2 通读全书（接了大模型）

一个 `Tier::Strong` 任务。全书文字（每章前加 `[[章号]]`，每句不编号以省字数）放进去；超过模型上下文的 60%（各端在 `Caps` 里报上下文大小）就按卷切，每卷一次，最后再用一次请求合并各卷的表。

要它回的 JSON（用结构化输出，schema 由核心给）：

```jsonc
{ "characters": [
    { "key": "c1",
      "names": [ { "text": "王熙凤", "kind": "full" }, { "text": "凤姐", "kind": "short" },
                 { "text": "凤丫头", "kind": "nickname" } ],
      "called_by": [ { "who": "c7", "as": "二嫂子" } ],
      "gender": "f", "age": "young",
      "traits": "荣国府管家奶奶，爽利泼辣，话快带笑",
      "speaks": true,
      "evidence": [ { "section": 3, "quote": "这熙凤听了，忙转悲为喜道" } ],
      "same_as": null,
      "revealed": null } ],
  "merges": [ { "a": "c1", "b": "c9", "evidence": { "section": 3, "quote": "…" }, "kind": "alias" } ],
  "groups": [ { "key": "g1", "names": ["众人", "丫头们"] } ],
  "narrator": { "person": "third", "who": null } }
```

提示词要点（模板放 `prompts/cast.v1.txt`）：只列**说过话**的人物；每个名字、每条合并都要给一句原文证据，证据必须逐字抄自原文；不确定是不是同一个人就不要合并；身份是后来才揭开的，填 `revealed`（从哪一章起读者才知道），不要提前合并。

### 5.3 校验（核心做，不信模型）

- 每条 `evidence.quote`：去掉空白和标点差异后，必须在指定章里逐字找到。找不到 → 在全书找；还找不到 → 这条证据作废。
- 一个名字没有任何有效证据 → 删这个名字。一个人物没有任何有效名字 → 删这个人物。
- 每条 `merges`：证据有效，且证据句里**同时出现**两边各至少一个名字，才合。否则不合，只在人物页提示“可能是同一个人”。
- 一个名字被两个人物同时要 → 两边都标 `ambiguous`，认人时这个名字不能单独当依据。
- 称呼类（母亲、老爷、师父、姐姐）只进 `called_by`，不进 `names`。
- 和规则收到的名字对账：规则有、模型没有的名字，保留为单独人物。

### 5.4 名字索引

所有名字建一个多模式匹配（Aho–Corasick，长名优先）。给任意一句，能列出里面提到了哪些人物、在哪个位置。后面认人、判断在场都用它。名字带章节范围（化名只在某几章有效）。

### 5.5 合并、拆分、改名（用户）

存在 `drama_user` 里，作用在“名字集合”上：声音、用户改的说话人都跟名字集合走。规则或模型升级后，只要集合里还有一个名字对得上就接得上。各端只拿 `CharId`，不自己比名字。

## 六、③ 拆场 `scenes.rs`

场是认人、环境音的基本单位。

- **规则先切**：章首；空行或分隔符（`***`、`※`）；句首出现时间地点跳转词（“次日”“三天后”“却说”“话分两头”“Meanwhile”“The next morning”）。
- **大模型修正**（和认人第二层合成一个请求，省一次读）：给一章带句号的原文，回 `[{first, last, place, place_kind, indoor, time, weather, crowd, present:[{who, enter, leave}]}]`。核心校验：区间连续、不重叠、盖满全章；`present` 里的人必须在人物表里。
- 一场超过 150 句台词的，按规则切点再切开（只影响请求大小，不影响环境音）。
- **在场表**：进场 = 第一次在本场被名字索引命中且是主语或说话人；模型给的 `enter / leave` 只用来缩小，不用来扩大。没接大模型时，在场 = 本场出现过名字的所有人。

## 七、④ 认人 `attribute/`

### 7.1 第一层：规则 `rules.rs`

只认书上写明的。输出 `basis = Explicit, decided_by = Rule`。

| 写法 | 例 |
|---|---|
| 说话词在前 | 宝玉笑道：“……” ／ Darcy said, "…" |
| 说话词在后 | “……”宝玉道。／ "…," said Darcy. |
| 说话词在中间（同一个 utterance） | “……”宝玉道，“……” |
| 一群人 | 众人都道：“……” → Group |
| 第一人称 | 我说：“……” ／ "…," I said. → 叙述者 |
| 承前省主语 | “……”说着又道：“……”——同一句里前面刚定了说话人 |

条件要严：说话词和引号之间只允许标点、“便、又、忙、因、乃、就”和状语（“冷笑着”“一面……一面”，≤ 12 个字）；主语必须被名字索引命中且不是 `ambiguous`；一句里命中两个人物且分不出谁是主语 → 不认。代词（他道、she said）规则不认，留给下一层。

验收：考卷上这一层的错 = 0。出现一例就收紧规则，不靠别的层兜。

### 7.2 第二层：整场精读 `ask.rs`

每场一个 `Tier::Fast` 任务。输入：

```
<cast>            ← 固定开头，可缓存：全书人物表（id、名字、称呼、男女、一句话特征）
<scene_before>    ← 上一场的最后 15 句（带已定的说话人），只作上下文
<scene>           ← 这一场原文。每句前 [句号]；每段台词用 ⟦q17⟧…⟦/q17⟧ 包起来
<known>           ← 规则已定的：q3=c12, q5=c1 …
<candidates>      ← 这场的候选：在场的人 + 上一场说过话的人 + GROUP + NARRATOR
```

要它回：

```jsonc
{ "quotes": [
    { "q": 17, "speaker": "c12",            // 只能是 candidates 里的 id，或 "UNKNOWN" / "NOT_SPEECH" / "OTHER"
      "other_name": null,                   // speaker = OTHER 时：原文里的名字
      "to": "c1",                           // 对谁说；不知道填 null
      "basis": "inferred",                  // explicit | inferred | content
      "anchor": 15,                         // basis=inferred 时：靠哪一句已知的台词推出来的
      "evidence": { "sentence": 212, "quote": "凤姐笑道" } } ],
  "scenes": [ … ] }                         // 第六节的拆场结果，同一个请求带回
```

提示词要点（`prompts/attribute.v1.txt`）：

- `explicit`：原文有说话词和名字或代词，证据抄那几个字；
- `inferred`：一来一回、承前省略、后文交代、称呼反推，必须指出 `anchor`；
- `content`：只能凭语气、立场、知道什么事来猜；
- **不确定就回 UNKNOWN**，UNKNOWN 不扣分，猜错扣分；
- 规则已定的也要回（用来对账，见 7.4 的“对账率”）。

核心校验：`q` 齐全且不多不少；`speaker` 在候选里；`evidence.quote` 在那一句里逐字找得到；`anchor` 指向的那句确实已定。一条不过，这一条作废；整份 JSON 结构不对或句数对不上，整场重发一次（附上错误说明），再不对放弃这一场的模型结果。

`OTHER` + 名字：名字在人物表里 → 改成那个人；不在 → 当成新人物候选（`provisional`），需要有 `explicit` 证据才收。

### 7.3 第三层：复核

对第二层里所有 **非 explicit** 的台词，再出一个 `Tier::Verify` 任务（优先换一家模型；只接了一家就换一档；只有一个模型就换提示词、温度不变）。**不给它看第二层的答案**，只给规则已定的。问法反过来：给出候选逐个排除——“这句不可能是谁说的、为什么”，最后回剩下的人。两层答案一致记 `agree = true`。

英文书可以多一个不花钱的第三意见：本机的小型引文归属模型（BookNLP 一类的编码器模型，候选见第十四节）。三个意见投票，规则同下。

### 7.4 约束和整场求解 `constraints.rs`、`solve.rs`

把一场里的台词按顺序排成 `q1…qn`，每句的候选是这场的人物加 `Unsure`。

**硬约束**（违反的候选直接去掉）：

1. 不在场的人不能说话（`OTHER` 新进场的除外）；
2. 规则、用户定的不可改；
3. 台词里用称呼点名叫的人不是说话人（“妹妹，你来”→ 不是那位妹妹；用 `called_by` 反查）；
4. 说话词里的代词和男女对不上的去掉（“她道”去掉所有男性；`Unknown` 的不去）；
5. 同一个 `utterance` 的各段同一个人；
6. 台词里自称的名字是说话人（“我王熙凤……”），用名字索引 + “我 / 俺 / 老夫 / I am”紧邻判断。

**软分**（初值，放 `calibrate.rs` 的常量表，考卷上调）：

| 来源 | 分 |
|---|---|
| 第二层选了这个人 | explicit +6 / inferred +4 / content +2 |
| 复核也选了这个人 | +3 |
| 复核明确排除了这个人 | −4 |
| 台词里出现这个人的名字（不是自称） | −2 |
| 和上一句台词是同一个人，中间没有旁白，且不是同一个 utterance | −3 |
| 两人对话段里和隔一句的台词是同一个人（一来一回） | +2 |
| 上一句的 `to` 是这个人 | +2 |
| `Unsure` | 0 |

求解：状态取相邻两句的说话人对 `(q[i-1], q[i])`，做 Viterbi（一场候选通常 ≤ 12 人，状态 ≤ 169，够快）；再做前向—后向，得到每句每个候选的后验 `post[i][c]`。“两人对话段”= 连续台词之间旁白 ≤ 1 句、且在场只有两人或 explicit 的说话人只出现两个。

### 7.5 定线 `calibrate.rs`

每句台词算特征：`basis`、两层是否一致、最高后验、第一第二名的差、这场的**对账率**（模型对规则已定台词的回答和规则一致的比例——模型连写明的都答错的场不可信）、在场人数、离最近的 explicit 台词隔几句。

用考卷的调试集训练一个小的逻辑回归（系数存成数据文件，按“模型组合”各存一份），输出 `p_correct`。阈值 `τ` 这样定：在**只打分的那份**考卷上，`p_correct ≥ τ` 的台词错率的 95% 置信上界 ≤ 0.1%（没有错例时需要约 3000 句以上才能下这个结论，所以考卷要够大）。

没有校准过的模型组合（用户接了一个没测过的模型）走保守规则，只收：

- `explicit` 且规则或另一层一致；
- `inferred` 且两层一致、`anchor` 有效、硬约束下后验第一名 ≥ 0.9；
- `content` 一律不收。

过线 → `decided_by = Model`；不过 → `Speaker::Unsure { top: 后验前两名 }`。

### 7.6 没把握清单和重算 `review.rs`

- 每条带：所在场、前后各 3 句、最可能的两人。
- 排序分 = 把这句设成第一候选后，重跑这场求解，有多少句从 `Unsure` 变成过线。分高的在前；同分按出现顺序。
- 用户选了一个人：写 `drama_user`，这场立刻重跑 7.4、7.5（不调模型，毫秒级）。如果这场还剩 ≥ 3 句没把握且接了大模型，后台重发一次第二层，把用户定的作为 `known`。
- 用户的选择（原句 + 答案）每本书留最近 20 条，作为示例拼进这本书后续章节的第二层请求里。
- 用户还能选“不是台词”“众人”“新的人物…”。

### 7.7 特殊情况

| 情况 | 做法 |
|---|---|
| 心里话 | `Thought`，说话人照认；念法见第九节 |
| 台词里转述别人的话（“他说‘你来’”） | 整句归外层说话人 |
| 书信、告示、诗 | `Quoted`；有写信人的记 speaker，用写信人的声音、读信的语气；没有的旁白念 |
| 多人齐声 | `Group`：对话声音，或在场的两三个声音叠着念（第九节） |
| 电话、隔墙、传音 | 说话人照认，`act.distance` 标出来 |
| 第一人称 | 叙述者是一个人物，旁白和他的台词同一个声音 |
| 化名、易容 | 揭开前是两个人物、同一个声音；人物页分两行 |
| 翻译腔的长名（费奥多尔·巴甫洛维奇） | 名字索引按“·”分段也建索引，段在书里唯一时可单独指人 |

## 八、⑤ 导演稿和声景数据 `direct.rs`、`sound.rs`

### 8.1 怎么念

1. **原文写了的先用规则**：说话词 → `Act` 的对照表（数据文件，中英各一份）。例：冷笑道 → Mocking/2；哭道 → Sadness/3 + Sob；喝道 → Anger/3 + Shout；悄声道、低声道 → Whisper；忙道、急道 → Fast；叹道 → Weary/1 + Sigh。`from_text = true`。
2. **没写的让模型推**：每场一个 `Tier::Fast` 任务（可以和下一场的认人并发），给已认好人的这场剧本，回每段的 `Act`。核心把模型推的 `level` 一律减 1（最低 0），`from_text = false`。
3. 旁白：每段标 `Plain / Tense / Lyrical`，章首章尾和场间的停顿长度。
4. **读音表**：通读全书时顺带要一份 `{词, 读音, 证据}`（人名、地名、多音字专名），核对词在书里出现过；合成前在段文字上替换成各引擎认的注音写法。用户能改。
5. **说话词念不念**：默认全念。“剧化”开关打开时，`rules.rs` 给每个 explicit 的说话词片段标 `tag_only`（只有“某某道”，没有动作描写）；合成时跳过这些片段，时间线上不出现，但高亮仍照原文走（这段高亮一闪而过，时长取 0）。

### 8.2 场景单和动静

`place_kind`（环境底按它取）先定这 40 来个，放数据文件：

```
室内：居室 厅堂 大殿 书房 厨房 客栈酒馆 茶楼 店铺 牢房 山洞 船舱 车厢 教室 办公室 医院 地下室
室外：庭院 街市 村庄 田野 山林 竹林 河边 海边 荒漠 雪地 城墙 战场 码头 桥上 墓地 夜路
现代：城市街道 地铁车站 咖啡馆 餐厅 机场 车内 工厂 酒吧
其他：梦境 回忆 未知
```

动静只收原文写了的。模型在拆场请求里顺带回：

```jsonc
"events": [ { "sentence": 212, "after_text": "推门进来", "what": "木门被推开",
              "kind": "door_wood_open", "evidence": "只见帘子一掀，推门进来" } ]
```

`kind` 来自一份固定清单（约 120 种：门、脚步、马、车、水、火、器物、兵器、天气、动物、人群、现代设备）；清单里没有的填 `other` 加文字描述。核心校验 `evidence` 逐字在原文里。每分钟最多 4 个、相邻至少隔 3 秒（按预计时长算），超出的按“离对话远的优先”留。

## 九、⑥⑦ 选角和合成

### 9.1 声音目录

每个可用的声音（系统、本机模型的预设、云端、克隆的、造出来的；各自怎么来见 9.4）一条记录：

```rust
struct VoiceInfo {
    id: VoiceRef, engine: Engine, langs: Vec<Lang>,
    gender: Gender, age: Age, tags: Vec<String>,   // 亮/厚/沙/软/冷/稳…
    embedding: Vec<f32>,                           // 声纹向量，各端量好交给核心
    can: VoiceCaps,                                // instruct（听指令）/ tags（非语言标签）/ context（看上文）/ 都不会
    loudness_lufs: f32,
}
```

各端第一次见到一个声音时，用它念一段固定的话，量声纹和响度，写进目录。两两相似度由核心现算（余弦）。

### 9.2 分配 `casting.rs`

人物按台词数排序。目标是让下面的总分最大：

```
总分 = Σ 合适(人物, 声音) × 台词数
     − λ × Σ 同场(人物a, 人物b) × 相似(声音a, 声音b)
```

- `合适`：男女对上 +3（对不上 −10，Unknown 0）、年纪段对上 +2 差一档 +1、语言会念是硬条件、声音会演（`can.instruct`）+1。
- `同场(a,b)`：两人在同一场都说话的台词数之和。
- 解法：台词数前 K 名（K = min(可用声音数, 24)）各占一个声音——先按台词数从多到少贪心选，再做两两交换的局部搜索直到没有改进。其余小角色从“龙套池”（按男女老少各留 2–3 个声音）里取，同场不撞。
- **声音不够或不合适**：出 `DesignVoice` 任务（给人物的一句话特征 + 男女 + 年纪 → 描述；用能按描述造声音的模型造一个，再用它自己念一段 10 秒参考音存下来，以后都用克隆这段参考音的方式合成，保证全书一致）。只给台词数前 K 名造。
- 旁白：目录里标了“适合旁白”的，或用户在朗读里选的那个。
- 结果写 `drama_voices`。用户换了某个人的声音，只作废这个人的片段缓存。
- 同一系列的下一本：按人物名字集合有交集沿用。

### 9.3 合成队列 `queue.rs`

- **单位**：一个 `Segment`。同一句里相邻、同声音、同 `Act` 的段先并成一个请求。
- **上文**：`Tts.context` 带上前两段（谁说的、文字），会看上文的引擎用得上，不会的忽略。
- **缓存键** = blake3(引擎 + 声音 + 文字（替换读音后）+ Act + 引擎版本)。
- **各引擎怎么用 Act**（各端的适配层做）：
  - 听指令的：把 `Act` 拼成一句自然语言（“压低声音，带着冷笑，语速稍快”）；
  - 用标签的：`[whispers]`、`[laughs]` 这类写进文字；
  - 都不会的（系统声音）：只用音量、语速，其余忽略——分角色照常，只是没有语气。
- **回听** `Check`：每个片段合成后各端做三件事，交回结论：
  1. 用听写模型转回文字，和原文按读音比（中文转无声调拼音，英文小写去标点），错字率 > 8% 或漏了 ≥ 3 个连续的字 → 不过；
  2. 量声纹，和这个声音的参考向量比，相似度低于“这个声音自己各片段的均值 − 3 个标准差”→ 不过；
  3. 削波、开头结尾静音 > 0.4 秒、总时长偏离“字数 × 这个声音的平均语速”超过 ±50% → 不过。
- 不过 → 重合成（换随机种子），最多 2 次；还不过 → 去掉 `Act` 用平常语气合一次；再不过 → 用旁白声音念，`drama_clips` 里记 `fallback`，人物页能看到有几处。
- 片段入库前：切掉头尾静音（−45 dB 以下）、各留 30 毫秒；响度归到 −20 LUFS（片段级），`Whisper` 再低 4 dB、`Shout` 高 2 dB。
- 存成压缩格式（AAC 或 Opus，单声道 64 kbps），不存 PCM。

### 9.4 声音来源（2026-11-16 定）

> 默认声音、手机上怎么听、克隆、自带声音这几件事后来另写了 `voices.md`，有出入的地方以那份为准。本节留着当“现有五种来源”的记录。

声音一共六种来源。核心不分来源，都是 9.1 的一条 `VoiceInfo`；下面定的是各端怎么拿到、谁能自动上场、许可和存放。

| 来源 | 怎么来 | 哪端有 | 会演 | 自动选角 | 花费 |
|---|---|---|---|---|---|
| **本机小模型（默认）** | Kokoro（中文用 v1.1-zh：55 个女声、45 个男声；英文日文用 v1.0），第一次朗读时下，约一两百 MB | 三端 | 不会 | 上 | 无 |
| 系统声音 | 系统自带；只当备选，不推荐 | 三端 | 不会 | 本机小模型没下时才上 | 无 |
| 云端声音 | 用户自己填 Key（OpenAI、ElevenLabs、Azure） | 三端 | 会 | 旁白选了这家才上 | 用户自付，按字数 |
| 本机模型的预设 | Qwen3-TTS 自带的几个音色 | Mac | 会 | 上（许可核过才上，见下） | 无，第一次下 2–4 GB |
| 造出来的 | 本机模型按人物描述念一句样句，之后照样句克隆 | Mac | 会 | 只给台词数前 K 名、现成声音不合适时造 | 无 |
| 克隆的 | 用户录或导入一段 10–30 秒的话 | Mac 本机模型；三端 ElevenLabs | 本机的会，ElevenLabs 的看它 | **不上**，只有用户亲手给某个人物设了才用 | 本机无；ElevenLabs 用户自付 |

**各端默认拿到什么**

- **平常朗读（三端）默认用本机小模型**，不是系统声音。第一次点朗读时问一次“下载朗读声音（多大）”，下的时候先用系统声音顶着，下完从下一句换过去。系统声音留在声音列表最下面一组，写“系统自带”。
- Mac：设置的朗读页多一行“会演的声音”（Qwen3-TTS），点了才下，下好后预设和造出来的声音进选角，带语气跟着生效。没下之前“带语气”一行照现在这样灰着写原因。
- 都没有时照降级表：分角色、不带语气。

**手机上听广播剧，从好到次**

1. **附近有自己的 Mac**：整批拿 Mac 做好的片段（会演、造出来的声音、环境音都在）。已做。
2. **接了云端**：会演，按字数花钱。已做。
3. **什么都没有**：本机小模型，一百来个声音够每个主要人物一个、同场不撞；不带语气，环境音、音效、过门照放。这是不花钱、不要 Mac 的人听到的样子，要保证它本身听着像样。
4. 之后：新款 iPhone（A17 Pro 以上）充电时用 Qwen3-TTS 0.6B 提前做带语气的片段。mlx-audio 的 Swift 版已支持这个模型，跑不跑得动、要多久，真机测过再定，不进 1.0。

**系统声音不够分**

- 选角前按语言数本机能用的声音，声纹相似度 > 0.9 的算一个（同一个引擎换音高的那几个）。
- 数出来男女各不到 2 个时，人物面板“听成一部剧”下面写一行“这门语言本机只有 n 个声音”，带一个去系统朗读声音下载页的入口。不弹窗、不拦着开始。
- 不够时照 9.2：台词多的先占，其余用对话声；不硬配不合男女的声音。

**克隆**

- 克隆的声音是某个真人的，不自动分给书里的人物；用户给谁设了就是谁，选角不动它。
- Mac 下了本机模型后，克隆走本机（存样句和它的文字，合成时照样句念），不用 Key。没下模型或在手机上，照旧走 ElevenLabs。
- 录之前那句“这是我的声音，或者我得到了本人同意”照旧必勾。

**参考音存哪、跟不跟着走**

- 造出来的声音：样句（WAV）、样句的文字、描述、男女年纪，存进这本书的广播剧数据里，跟书一起进快照和同步。本机声音服务不留底，合成时由 App 把样句带过去。这样换机器、重装后同一个人物还是同一个声音。
- 克隆的声音：只留在录它的那台设备上，不同步、不进快照（现状不变）。别的设备上这个人物由旁白声音念。
- 局域网从 Mac 拿片段时只拿做好的片段，不拿参考音。

## 十、怎么考

### 10.1 考卷

`fixtures/drama/gold/<书>/<章>.json`：每句台词的标准答案 `{loc, text_head, speaker_names:[…], basis, ambiguous: bool}`，加上这一章的人物别名表。`ambiguous = true` 的句子（标的人自己也拿不准）不计入错，只要求系统判 `Unsure`。

- 中文：古典白话、现代小说、网文写法、翻译小说；英文小说。各 ≥ 6 章。
- 专门的难题：多人混战、整章不写说话人、无引号体、第一人称、化名。
- 总量 ≥ 6000 句台词，分**调试集**（40%）和**只打分集**（60%，提示词、规则、系数都不许看着它调）。
- 只用公版文字或自己写的同类文字。公开的标注语料许可允许的，放在仓库外当加考。

### 10.2 打分

`yuyue-cli drama eval --gold fixtures/drama/gold --llm <配置>` 输出一张表并写 JSON。大模型的回答按请求内容的摘要缓存在本地，重复跑不花钱；CI 上只跑用缓存能跑的部分。

| 量 | 线 |
|---|---|
| 规则层：错 | 0 句 |
| 整体：配了人的里面配错的 | ≤ 0.1% |
| 整体：配到人的比例 | ≥ 97% |
| 不是台词被当成台词 / 台词漏了 | 各 ≤ 0.1% |
| 人物并错（主要人物） | 0 对 |
| 模型回答校验不过的比例 | ≤ 2% |
| 清完清单的点击数（三十万字折算） | ≤ 60 |
| 拆段 + 规则认人整本《红楼梦》 | ≤ 2 秒 |
| 合成回听后仍有错字的片段 | ≤ 0.5% |
| 导入到能听 | ≤ 60 秒 |

比上一次提交差就不过。

### 10.3 听着考

同一章盲听“一个声音”和“广播剧”：分得清谁是谁吗、有没有哪句出戏、环境音烦不烦。每次改声音模型、混音参数都听一遍。

## 十一、⑧⑨⑩ 声景、时间线、混音

### 11.1 声音素材

- **内置库**（随 App 下载，不进安装包）：环境底每个 `place_kind` × 昼夜 / 天气 2–4 条，每条 60–120 秒、能无缝循环；点状音效每个 `kind` 3–5 个变体。只收许可允许再分发的（CC0、自己录的、或只限非商用的），清单文件记来源和许可。
- **生成**：清单里没有的（`other`）或库里没有合适变体的，出 `Sfx` 任务，用文字生成音效的模型做（本机或用户接的云端），做完进这本书的缓存。没有这个能力就不放。
- 素材统一成 48 kHz、环境底立体声、点状音效单声道，响度归一。

### 11.2 时间线 `timeline.rs`

一场一条时间线（一场的片段都合成好了才出；播放时提前备好下一场）：

```rust
struct Timeline { scene: SceneId, duration: f64, items: Vec<Item> }
enum Item {
    Voice { clip: ClipId, at: f64, gain_db: f32, pan: f32, reverb_send: f32, filter: Filter, loc: Loc, span: Span },
    Bed   { asset: AssetId, from: f64, to: f64, gain_db: f32, fade_in: f32, fade_out: f32 },
    Spot  { asset: AssetId, at: f64, gain_db: f32, pan: f32 },
    Music { asset: AssetId, at: f64, gain_db: f32 },
}
```

**间隔**（片段之间的静音）：

| 之间 | 秒 |
|---|---|
| 同一句里旁白 → 台词、台词 → 旁白 | 0.15 |
| 换人说话 | 0.30 |
| 抢话（上一句以“——”“…”结尾被打断） | 0.05 |
| 句与句（同一个声音） | 引擎自己的句尾，补到 0.25 |
| 段与段 | 0.60 |
| 场与场 | 1.50（环境底在这里交叉淡化 1.2 秒） |

**空间**：旁白居中、不进房间混响；主要人物按本场出场顺序分到 −0.25…+0.25 的声像；`Far` 降 6 dB + 低通 3 kHz + 多送混响；`Offstage` 降 9 dB + 低通 1.5 kHz；`Thought` 居中、不送混响、轻微低切，听起来贴耳；电话加带通 300–3400 Hz。

**混响**：每个 `place_kind` 对应一个预设（房间大小、衰减时间、湿度）。室外几乎没有。

**点状音效的时间**：`after_text` 在片段文字里的位置 ÷ 片段字数 × 片段时长；引擎给了字级时间就用字级时间。放在那个字之后、且不压在下一段台词的头 0.2 秒里，必要时把下一段往后推最多 0.4 秒。

**电平**：人声总线为准；环境底 −30 LUFS 左右（比人声低 10–14 dB），有人说话时再让 3 dB；点状音效峰值比人声低 6 dB；音乐过门只在场间，人声进来前 0.5 秒收完。总输出 −16 LUFS、真峰值 ≤ −1 dBTP，末端加限幅。

每句的起止时间 = 这句各片段的最早和最晚时间，写回给播放器做高亮、跳转、按句定时。

### 11.3 混音器 `core/yuyue-mix`

一个独立的 Rust crate，三端共用，导出也用它：

- 输入：`Timeline` + 取 PCM 的回调（各端解码好给进来，或用纯 Rust 解码库）；输出：按块拉取的立体声 48 kHz 浮点 PCM。
- 四条总线（人声、环境、音效、音乐）各带音量和开关，实时可改；侧链让路；一个算法混响（FDN 或 Freeverb 一类，参数走预设）；每路的增益、声像、一阶 / 二阶滤波；末端限幅。
- 实时回调里不分配内存、不加锁（参数用无锁队列传）。
- Apple 用 `AVAudioSourceNode` 拉，Android 用 Oboe 的回调拉。倍速在混音之后用系统的变速不变调。
- 离线模式：同一套代码跑到底，写文件——导出一章或整本（m4b，带章节）。
- 测试：给定时间线和合成的测试信号，输出逐样本可复现；电平、让路量、限幅有单元测试。

关环境音 = 环境总线静音；换某人的声音 = 作废他的片段、重合成、重出受影响场的时间线；改一句是谁说的 = 重合成这一句。都不动别的。

## 十二、花费、隐私、降级

- **读文字**：通读一遍（Strong）+ 每场精读（Fast）+ 非写明台词复核（Verify）+ 导演稿（Fast）。输入总量约为全书的 3–4 倍，输出很少。人物表作为固定开头走缓存；不急的章节可走批量接口。开始前核心按字数给一个估计的输入 / 输出量，各端换算成钱给用户看，用户点了才开始。
- **声音**是大头：本机不花钱但慢，云端按字数。默认本机提前合成；云端由用户自己接。
- **隐私**：书的文字只发给用户自己接的服务，开之前写清发给谁。
- **降级表**：

| 少了什么 | 还有什么 |
|---|---|
| 没接大模型 | 规则认人（只有写明的台词分角色）、规则导演（只有原文写明的语气）、内置环境音按章给一个默认底或不放 |
| 声音不会演 | 分角色、不带语气 |
| 没有生成音效的能力 | 只用内置库 |
| 手机本机合不动 | 用 Mac 做好传过来的片段，或云端；或只分角色用系统声音 |

## 十五、风险和退路

| 风险 | 退路 |
|---|---|
| 配到人的比例到不了 97% | 守错率、放比例：多几句没把握，对话声音念 |

## 补做（2026-11-16）

- **声纹接上了真模型**：3D-Speaker 的 CAM++（中文通用版，Apache-2.0）。`scripts/align-bench/export_speaker.py` 按官方结构重写一份 PyTorch，载入原始权重，同时出 Core ML（`SpeakerPrint.mlmodelc.zip`，13 MB，半精度）和 ONNX（`speaker_print.onnx`，28 MB），两份和原始模型在 60–1500 帧上余弦 ≥ 0.9999。原先手上那份 sherpa 导出的 onnx 在最后一段不满 100 帧时算错（短片段余弦只有 0.69），不用了。

- **片段改存压缩格式**：AAC 单声道 48 kHz 64 kbps。Apple 存在 CAF 里（文件名不变，去掉写入时留的 28 KB 空白块，3 秒约 26 KB，原来 576 KB）；Android 存 m4a（`ClipAudio.kt`）。读回来逐样本对齐：Apple 系统自己去掉编码器前导；Android 系统不告诉前导多长，第一次用时编一个脉冲再解回来量一次（模拟器上 2048 个样本），249 段实测对齐误差 0。旧的 PCM / `.f32` 片段照样能读。设备之间传片段仍按 float 传，新旧版本互通。
