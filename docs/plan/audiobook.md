# 语阅 · 有声书技术方案

> 日期：2026-11-12 ｜ 状态：做法定了，等第 0 步实测 ｜ 这份写给动手实现的人看：模块、数据、算法、参数、验收线都在这里。界面另出原型，原型确认前不写界面代码。

有声书指用户自己手里的录音（真人念的 m4b、mp3 等），不是 App 合成的朗读。

## 〇、给实现者

1. **核心不联网、不跑模型**。`core/yuyue-core`（Rust，经 uniffi 给三端）只做纯计算：解析容器里的章节、排序、读音归一、比对、对齐的动态规划、对照表、进度换算。解码、人声检测、听写、声学模型都由各端跑，把结果交回核心。三端结果一样，核心能在 `cargo test` 里全量测试。
2. **先读再写**。核心里已有用途相近的文件：`audio.rs`（导入、排序、章节）、`m4b.rs`（章节标记）、`forced.rs`（拿声学模型的输出做强制对齐）、`align.rs`、`listening.rs`（对齐结果的存取）、`segment.rs`（分句）；Apple 端有 `Speech/AudiobookPlayer.swift`。能接着用的接着用；本文的类型名、函数名是建议，和现有风格冲突时以现有风格为准，但**数据的含义和验收线不能改**。
3. **顺序**：先做第十一节的考卷和打分，再做对齐。没有打分的算法改动不合并。
4. 每一层的产物带版本，上游变了只重做下游受影响的部分。**用户钉的锚永远最大**。
5. 本文里的阈值是起点，写成常量集中放一处，第 0 步实测后调；调了要在这里改数。

## 一、要做成什么样

一句话：**一本书，眼睛和耳朵用同一个进度。**

1. **拖进来就能听**。一个文件、一个文件夹、一个压缩包都行；章节、封面、作者自己认出来。
2. **自己找到对应的电子书**。书架上有同一本，自动配上，书架上还是一本书。
3. **读到哪，听到哪**。晚上看到第几句，早上从那一句接着念；听了一路，打开书就在那一页，正在念的那句亮着。
4. **点哪句念哪句**。搜一个词，直接跳到念这个词的地方。
5. **听的时候也能划线**。按一下，刚念完的那句成为一条带原文的划线。
6. **没有电子书也一样**。录音自己转成文字版，照样能看、搜、划线、查词。
7. **对不上的地方说实话**。多出来的（片头、广告）标出来可跳过；没念的（脚注、删节）标出来，可以让朗读补上。
8. **一台做完，别的直接用**。对照表很小，跟着同步。

## 二、整体

```
录音文件
  │ ① import     容器、排序、章节、封面、身份
  │ ② listen     人声检测 → 听写（带字级时间）            ← 各端跑模型
  │ ③ match      配上哪本书、是不是同一个版本
  │ ④ anchor     读音归一 → 找锚 → 逐句比对（粗，±1 秒）
  │ ⑤ refine     声学强制对齐（细，±50 毫秒）→ 吸到停顿    ← 各端跑模型
  │ ⑥ grade      每句的把握；低的降级；多出来的、没念的
  ▼
对照表 SyncMap（句子 ↔ 时间；带版本；同步）
  ├ 播放器只认时间
  ├ 阅读器只认句子
  └ 进度存句子，用对照表换算
```

### 2.1 代码放哪


### 2.2 核心和各端：作业制

```rust
fn audiobook_next_task(book_id: String, focus: Option<f64 /*正在听的秒*/>) -> Option<Task>;
fn audiobook_submit(task_id: String, result: TaskResult) -> Result<Progress>;

enum Task {
    Probe      { id, files: Vec<String> },                                  // 时长、采样率、容器里的章节和标签
    Vad        { id, file: u32, from: f64, to: f64 },                       // → 人声段、音乐段
    Transcribe { id, file: u32, segments: Vec<(f64, f64)>, lang: Lang, quality: Quality /*Fast|Careful*/ },
    Align      { id, file: u32, from: f64, to: f64, units: Vec<String> },   // → 每个 unit 的起止，或发射矩阵
    Polish     { id, system: String, user: String, schema: String },        // 可选：大模型整理文字版
}
```

任务幂等，各端崩了重新取就接上。一个文件按 10 分钟一块出 `Vad` + `Transcribe`，`focus` 所在的块最先出。

各端的活：

| 任务 | Apple | Android |
|---|---|---|
| 解码成 16 kHz 单声道浮点 | AVAssetReader / AVAudioConverter | MediaExtractor + MediaCodec |
| 人声检测 | 小模型（Core ML） | 同一个模型（ONNX Runtime / LiteRT） |
| 听写 | 新系统用系统自带的长录音转写；否则开源模型 | 开源模型 |
| 强制对齐 | 声学模型（Core ML / MLX） | 同一个模型（ONNX / LiteRT） |

模型不进安装包，第一次用时下载，校验摘要。

## 三、① 导入 `import.rs`

### 3.1 认得的

| 来源 | 章节从哪来 |
|---|---|
| m4b / m4a | `chpl` 原子；QuickTime 章节文字轨；两个都有时用条目多的 |
| mp3 | ID3v2 的 `CHAP` / `CTOC` 帧；某些借阅平台写在自定义标签里的 XML 章节标记 |
| ogg / opus / flac | Vorbis 注释里的 `CHAPTERnnn` / `CHAPTERnnnNAME`；flac 的 cuesheet 块 |
| 外挂 `.cue` | 逐条 |
| 一章一个文件 | 每个文件一章，标题取标签里的标题，没有取文件名去掉序号 |
| EPUB 3 自带朗读时间 | 直接读出对照表（第十节），跳过 ②–⑤ |
| zip | 解开后按文件夹处理 |

带版权保护的加密文件（解不了码）：导入时报“这个文件有版权保护，打不开”，不入库。

### 3.2 排序

排序键依次是：碟号、曲目号（标签里有且不重复才用）、文件名的自然序。自然序：数字段按数值比；认中文数字（第十二回、卷三）、罗马数字（Part IV）、全角数字。排完的顺序交给界面给用户过目，可拖动改；用户改的顺序存下来。

### 3.3 身份

`audio_id` = blake3(每个文件的 [大小, 前 1 MB, 后 1 MB] 依次拼起来)。不依赖文件名和路径。另一台设备后拿到同一份录音，算出同一个 id，自动接上已同步的对照表。

### 3.4 入库

- 原文件原样放进书库；从外接盘、网盘来的可选“留在原处”，只记位置（Apple 用安全书签）。不转码。
- 导入只做 `Probe`（毫秒到秒级），马上能听。②之后的全在后台。
- 没有章节的大文件：先按“每 30 分钟一段”显示临时章节；听写完后重切——配了电子书的照书的目录（每章第一句的时间）；没配的找“≥ 2 秒的停顿后面紧跟着念出‘第×章 / Chapter × / 卷× / Part ×’”。

## 四、② 听写

### 4.1 人声检测

每 10 分钟一块，小模型出每 30 毫秒一帧的“有人说话”概率。后处理：

- 概率 ≥ 0.5 连续 ≥ 250 毫秒算人声段；人声段之间 < 150 毫秒的缝合并；
- **停顿表**：所有 ≥ 150 毫秒的非人声缝，记起止——第七节吸句首用；
- **音乐**：非人声且能量不低（比本文件人声段的中位能量低不到 20 dB）持续 ≥ 5 秒，标 `music`；
- 人声段切成 ≤ 30 秒的听写单元，切在停顿表里最长的缝上。

### 4.2 听写

每个单元出：`[{ text, t0, t1, conf }]`，字级（中文按字，英文按词）。模型只给句级时间的，各端用同一个声学对齐模型把字级时间补上再交。

- `Quality::Fast`：对齐用。同音字、人名错了无所谓。
- `Quality::Careful`：只在做文字版（第十节）时用，换大一档的模型。
- 语言：配了电子书的用书的语言；没配的先听写头 2 分钟自动判。

存：`transcript.rs` 按文件分块存，字串 + 时间差分 + varint，再整体压缩。十几个小时的书约 1–2 MB，只存本机，不同步（对照表才同步）。

### 4.3 排队

- 正在听的块 → 它后面的两块 → 从头到尾。
- 手机：正在听的那一章马上做；其余只在充电且屏幕关着时做，或用户点“现在就做”。Mac：导入后直接做完。
- 别的设备已经同步来了对照表：整个 ②–⑥ 跳过。

## 五、读音归一 `phon.rs`

对齐的所有比较都在“读音串”上做，不在字上做。书和听写结果过同一个函数：

```rust
struct Tok { key: u32 /*读音的编号*/, src: u32 /*在原文里的字符位置*/ }
fn phon(text: &str, lang: Lang) -> Vec<Tok>;
```

**中文**：

1. 繁体转简体；全角转半角；去标点和空白。
2. 数字和符号按念法展开成汉字。有两种念法的生成**两条**，比对时都算对（见 6.2）：
   - 年份：`1978年` → 一九七八年；
   - 数目：`1978` → 一千九百七十八 **或** 一九七八；`2` → 二 **或** 两；
   - 小数、百分比、分数、时间、日期、货币：`3.5%` → 百分之三点五；`3:05` → 三点零五分 **或** 三点五分；
   - 西文字母：逐个按字母名（`A` → 诶）；整词英文按英文规则。
3. 每个字取**不带声调的拼音**作 `key`。多音字取**所有读音的集合**，比对时集合有交集就算相等。前后鼻音、平翘舌不分（`in/ing`、`en/eng`、`z/zh`、`c/ch`、`s/sh`、`n/l` 归并）——听写模型和念的人都常混。
4. 儿化的“儿”、语气词“啊呀呢吧嘛”权重减半（缺了、多了罚得轻）。

**英文**：小写；去标点；缩写展开（`Mr.` → mister，`Dr.` → doctor **或** drive）；数字展开成词；`key` = 词。比对时词相等，或长度 ≥ 5 且编辑距离 ≤ 1，算相等（听写的拼写小错）。

其他语言：先只做“小写、去标点、按词”，以后按需加。

测试：数字、日期、货币、多音字各列一张表，逐条断言。

## 六、③④ 配书和粗对齐

### 6.1 配上哪本书 `matchbook.rs`

每本书预先建一个索引（导入电子书时顺手建，存本机）：书的读音串里所有长度 `K` 的片段的哈希 → 位置。`K` = 中文 6 个音节，英文 4 个词。

录音这边：头 3 分钟 + 中间随机 3 处各 2 分钟的听写结果，取所有 K 片段去每本书的索引里查，**命中率** = 命中的片段数 ÷ 总片段数。

| 命中率 | 判为 | 做法 |
|---|---|---|
| ≥ 0.5 | 同一个版本 `same` | 逐句对齐 |
| 0.2 – 0.5 | 修订或删节 `revised` | 逐句对齐，缺口如实标 |
| 0.03 – 0.2 | 另一个译本或改写 `chapter-only` | 不逐句对。按章对上，或用文字版 |
| < 0.03 | 不是这本书 | 不配 |

多本书都过线取最高的；最高的两本差 < 0.1（同一本书的两个版本都在书架上）取命中率高的，并在详情里让用户能换。全都不过线 → 没有电子书，走第十节。书名、作者只用来在候选多时排序，不作判断依据。

### 6.2 找锚 `anchor.rs`

对 `same` / `revised`。书的读音串记 `B`，整份听写的读音串记 `A`。

1. **按章定范围**：录音的每一章（或每个文件）取头 2 分钟的 K 片段，在书的索引里投票，票最多的书的章就是它对应的章；连续几章投给书的连续几章，就把范围定下来。投不出来的章（纯音乐、片头）先空着。书和录音章节顺序不一样没关系——每章各自找。
2. **找锚**：在对应的章范围内，取“在 `A` 里只出现一次、在 `B` 里也只出现一次”的 K 片段作候选锚。按 `A` 的位置排序，在 `B` 的位置上取最长递增子序列，丢掉乱序的。相邻锚如果紧挨着就并成一段。
3. **锚的密度**：正常的书每分钟有几十个锚。相邻两个锚之间在 `A` 里超过 90 秒或在 `B` 里超过 600 个音节没有锚 → 这一段记“疏”，后面单独处理（6.4）。

### 6.3 锚之间逐句比对

相邻两个锚之间，`A` 的一小段和 `B` 的一小段做全局比对（带仿射缺口的动态规划）：

| | 分 |
|---|---|
| 读音相等（含多音字交集、两种念法之一、英文近似） | +2 |
| 不等 | −1 |
| 缺口开一个 | −2 |
| 缺口延长一个 | −0.5 |
| 轻读的字（语气词、儿化） | 上面各项减半 |

只在对角线两侧 ±max(50, 长度差 + 20) 的带里算。数字的两种念法：在 `B` 里把那几个 `Tok` 标成“二选一组”，动态规划到这里时两条路都走，取高的。

比对完，书的每一句（核心已有的分句）得到：

- 它的字里有多少对上了（**覆盖率**）；
- 对上的第一个字、最后一个字在 `A` 里对应的时间 → 粗的起止（误差一两秒）。

然后分类：

- 覆盖率 ≥ 0.6 → `aligned`（进第七节精修）；
- 覆盖率 < 0.2，且它在 `A` 里对应的时间跨度 < 这句“按语速该有的时长”的 30% → `unread`（没念）；
- 中间的 → `weak`（第八节按粗的处理）；
- `A` 里连续 ≥ 8 个字（或 ≥ 3 秒）没有对上书的任何字 → `extra`（多出来的话），记起止和听写出的文字。

### 6.4 “疏”的段

可能是：大段删节、大段多出来的话、听写在这里质量很差（背景音乐）、书里是外文或诗。做法：把 K 降到一半再找一遍锚；还找不到 → 这段的书句全记 `weak` 或 `unread`（看时间跨度够不够念完它们），这段的录音如果有人声且对不上任何书句，记 `extra`。不硬对。

### 6.5 复杂度

一本 50 万字、15 小时的书：建索引和找锚是线性的；锚之间的比对因为段很短（几十到几百个音节），总共不到 1 秒。整个 ③④ 目标 ≤ 3 秒。

## 七、⑤ 精修 `refine.rs`

粗对齐靠的是听写模型的字级时间，偏差一两百毫秒到一两秒。精修用**给定文字、算每个字在哪一毫秒**的声学模型。

### 7.1 出窗口

把相邻的 `aligned` 句子攒成窗口：总时长 15–25 秒，切在停顿表里的长缝上；前后各多带 1.5 秒录音。每个窗口一个 `Align` 任务，`units` = 这几句的文字（按第五节展开数字之后的念法，用比对时胜出的那一种）。

### 7.2 各端交回什么

两种都收，由模型的类型决定：

- **直接给时间的对齐模型**：每个 unit（句）以及每个字 / 词的起止时间和得分。
- **CTC 声学模型**：每帧每个符号的对数概率矩阵 + 帧长。核心自己做网格上的最优路径（核心已有这类代码），得到每个字的起止帧和平均对数概率。文字要先转成模型的符号（中文转拼音字母或模型自己的字表；这一步的表跟模型一起下发）。

窗口首尾允许跳过若干帧不对应任何字（因为多带了 1.5 秒）。

### 7.3 吸到停顿

每句精修后的起点 `s`、上一句的终点 `e`：

- 在停顿表里找和区间 `[e − 0.15, s + 0.15]` 有交集的最长的缝 `[g0, g1]`；
- 有 → 这句的起点 = `max(g0, g1 − 0.12)`（留 120 毫秒的气口，不切字头），上一句的终点 = `min(g1, g0 + 0.25)`；
- 没有（两句连着念）→ 起点 = 终点 = `(e + s) / 2`，这句标 `no_gap`（按句跳转时会多带 60 毫秒的淡入）。

### 7.4 字级时间

精修顺带得到每个字的时间，存下来（可选，体积大约是句级的 8 倍，只存本机）：用于“搜一个词跳到那个词”“点一个词从这个词念”“逐词高亮”（学外语时开）。同步的对照表只有句级。

## 八、⑥ 把握、降级、多出来的、没念的 `grade.rs`

### 8.1 每句的把握

特征：

- 粗对齐的覆盖率；
- 精修的平均得分（按这本书所有句子的分布标准化——不同录音绝对值差很多）；
- 精修起点和粗对齐起点差多少；
- 时长是否合理：`实际时长 ÷ (字数 × 这本书的平均每字时长)` 落在 0.4–2.5；
- 前后句是否也 `aligned`；
- 起点是否吸到了停顿。

用考卷的调试集训练一个小的逻辑回归（系数存成数据文件），输出 `conf` = “起点落在正确停顿里”的概率。

### 8.2 三档

| 档 | 条件 | 给什么 | 界面上 |
|---|---|---|---|
| `auto` | `conf ≥ 0.9` | 精确起止 | 正常高亮；点这句从句首念 |
| `spread` | `conf < 0.9`，或 6.3 的 `weak` | 不给精确时间：在前后最近的两个 `auto` 句之间，按各句“字数 × 轻读权重”匀开 | 高亮照走（稍不贴）；点这句 = 跳到这一小段第一句的起点 |
| `chapter` | 一章里 `auto` 不到 50% | 这章只有章的起止 | 这章不逐句高亮，书页顶上写明；翻页按时间比例大致跟随 |

阈值 0.9 在只打分的考卷上校：`auto` 档里“点一句念的是另一句”的比例 ≤ 0.1%。

### 8.3 用户钉锚

长按句子 →“从这里对准”：把播放器此刻的时间钉给这一句，存 `by: user`。然后以它为新锚，重跑前后各 2 分钟的 6.3、第七节、8.1。用户钉的在以后任何重算里都当已知条件。也可以反过来：拖动进度到对的地方，再点“就是这句”。

### 8.4 多出来的 `extras`

```rust
struct Extra { t0: f64, t1: f64, kind: ExtraKind /*Music | Speech*/, text: Option<String>, place: Place /*Head|Tail|Middle|ChapterGap*/ }
```

- 全书开头到第一句书文之前、最后一句书文之后 → `Head` / `Tail`：默认跳过。
- 章与章之间只有音乐、≥ 4 秒 → `ChapterGap`：默认压到 1.5 秒。
- 书中间的人声 → `Middle`：默认照放。
- 跳过时界面闪一条“跳过了片头 · 点这里听”（5 秒内可退回）。每本书可单独改这三项。

### 8.5 没念的 `unread`

书页上颜色淡一档。开了“用朗读补上”（默认关）：播到 `unread` 句子前一句的终点时，暂停录音，用朗读的声音念完这些句子，再从下一句的起点接回；界面上写明这段是朗读。脚注、图注这类本来就不在正文流里的不补。

## 九、对照表 `map.rs`、进度 `progress.rs`

### 9.1 SyncMap

```rust
struct SyncMap {
    audio_id: String, book_id: String,
    match_kind: MatchKind,               // Same | Revised | ChapterOnly | Transcript | Imported
    files: Vec<FileInfo>,                // 时长；整本的时间 = 各文件首尾相接
    chapters: Vec<ChapterSync>,          // { title, t0, book_section: Option<u32>, mode: Sentence|ChapterOnly }
    rows: Vec<Row>,                      // 按书的顺序，每句一条
    extras: Vec<Extra>,
    version: MapVersion,                 // 对齐算法版本、书文字摘要、模型名
}
struct Row { loc: Loc, t0_ms: u32, t1_ms: u32, by: By /*Auto|Spread|User|Unread*/, conf: u8, no_gap: bool }
```

编码：按章分块，`t0` 相对上一句的差分 + varint，`t1 − t0` 同样；整块压缩。整本几百 KB。两个查找都是二分：

```rust
fn time_to_loc(&self, t: f64) -> Hit;        // Hit::Sentence(loc, 句内比例) | Hit::Extra(i) | Hit::Gap(前一句)
fn loc_to_time(&self, loc: Loc) -> Option<f64>;   // Unread → 下一句已念的起点
fn sentence_bounds(&self, t: f64) -> (f64, f64);  // 按句跳、念完这句停 用
```

注意录音的顺序可能和书不一样（先念后记）。所以另存一份**按时间排序的下标**；`rows` 本身按书的顺序。

### 9.2 进度

- 配了书：存 `Loc + 句内比例(0–1)`；播放器要秒时用 `loc_to_time` 换。换一份录音、换一个朗读声音，进度都在。
- 没配书、还没对齐：存秒。对齐完成后把秒换成 `Loc`，以后存 `Loc`。
- 每 5 秒、每次暂停、每次切到后台各存一次。带设备名和时间戳同步。
- 两台设备都有进度：打开时如果别的设备的进度更新且差 ≥ 30 秒，问一句“跳到〈设备名〉上听到的地方？”，不悄悄跳。

### 9.3 聪明地倒回

暂停后再播，往回退：

| 暂停了多久 | 退到 |
|---|---|
| < 10 秒 | 不退 |
| 10 秒 – 2 分钟 | 这句的开头 |
| 2 分钟 – 1 小时 | 上一句的开头 |
| 1 小时 – 1 天 | 这一段的开头（最多 30 秒） |
| > 1 天 | 这一段的开头（最多 60 秒）；接了大模型且用户开了“前情提要”，另给一段文字提要，不念出来 |

没有对照表时，“句的开头”换成“往回找最近一个 ≥ 0.4 秒的停顿”。被电话、导航语音打断后恢复：退到这句开头。

## 十、没有电子书：文字版 `textbook.rs`；标准格式 `export.rs`

### 10.1 文字版

1. 全书用 `Quality::Careful` 重新听写（后台，优先级最低）。
2. **标点和分句**：听写模型带标点的直接用；不带的按停顿补（≥ 0.35 秒逗号、≥ 0.6 秒句号）再过核心的分句。
3. **分段**：≥ 0.9 秒的停顿另起一段；一段超过 400 字的在最长的停顿处再分。
4. **分章**：容器里的章节；没有就按 3.4 的办法。
5. **可选整理**（接了大模型、用户点了才做）：出 `Polish` 任务，每次给约 2000 字，要它只改同音错字和前后不一致的人名，回 `[{句号, 原字, 改成}]`。核心校验：改前改后读音相同（5 的 `key` 相等）且句数不变，否则不收。
6. 产物存成一本“合成的书”，结构和导入的电子书一样（章 → 段 → 句），阅读器不用改。它的对照表直接来自听写的字级时间（再过第七节吸到停顿），`match_kind = Transcript`。书页顶上写明“这是录音转出来的文字，可能有错字”。
7. 以后用户导入了真的电子书：重新走 ③–⑥。原来在文字版上的划线，按“划线那几个字的读音串”在新书里找（要求唯一且在对应时间附近），找到的搬过去，找不到的留在文字版并提示。

### 10.2 标准有声电子书（EPUB 3 自带朗读时间）

- **导入**：读每个章节对应的时间文件，里面是“这个文字片段 ↔ 这个音频文件的这一段”。把文字片段对到核心的句子上（一个片段可能是一句、半句或一段）：片段和句子一一对上的直接用；一个片段含多句的，片段内按字数匀开，记 `Spread`。`match_kind = Imported`。
- **导出**：把 `SyncMap` 写成同样的格式，连同电子书和录音打成一个文件（或只导出时间文件）。`Spread` 的句子合并成一个片段导出，不假装精确。

## 十一、怎么考

### 11.1 考卷（不靠人一句句标）

`scripts/` 里的脚本：拿“每句单独录好的语音”按顺序拼成一本有声书，每句从哪开口是精确知道的。每本出这些变体：

| 变体 | 模拟什么 |
|---|---|
| 照念 | 基准 |
| 随机删掉 6% 的句子，另删掉连续的一整段 | 删节、没念的脚注 |
| 开头、结尾、中间各插 30–60 秒不在书里的话 | 片头、导读、广告 |
| 开头垫 20 秒音乐；章与章之间垫 5 秒音乐 | 过门 |
| 全程垫 −20 dB 的背景音乐（只做一份） | 广播剧式录音，应当降级 |
| 把书的文字换掉 5% 的句子（改写） | 修订版 |
| 句间停顿随机缩到 0–0.1 秒（10% 的句子） | 连着念 |
| 把章节顺序换两章 | 顺序不同 |
| 用另一本书的文字去配 | 应当判“不是这本” |

语料：英文用公开的朗读语料（一个人读一章的那种）；中文要有**干净的真人连续朗读**（公版朗读录音，自己切句、人工核一遍句界），再加系统声音合成的作补充——不能只有合成的。总量 ≥ 6 小时、≥ 4000 句，分调试集和只打分集。

另备 3–5 本真的有声书 + 电子书（公版），每本人工抽查 100 句，记在表里。

### 11.2 打分

`yuyue-cli audiobook eval`。模型的输出（听写、对齐）按输入摘要缓存，改了核心的算法重跑只要几十秒。

| 量 | 线 |
|---|---|
| `auto` 档：起点偏出正确停顿超过 0.3 秒 | ≤ 1% |
| `auto` 档：差一整句以上（点一句念的是另一句） | ≤ 0.1% |
| 干净、同版本：`auto` 档的比例 | ≥ 97% |
| 没念的句子被给了 `auto` 时间 | ≤ 0.5% |
| 念了的句子被判成没念 | ≤ 1% |
| 片头片尾没标出来 / 标多了吞掉正文 | 0 / 0 |
| 书中间多出来的话：被放出来算进某句的秒数 | 如实记，逐版下降 |
| 全程背景音乐那份 | 判为 `chapter` 档，不出 `auto` 的错句 |
| 另一本书、另一个译本 | 100% 判对 |
| ③④（配书 + 粗对齐）整本用时 | ≤ 3 秒 |
| 整本做完（含听写） | Mac ≤ 20 分钟 / 15 小时的书；手机一夜（第 0 步后写准） |
| 拖进来到能听 / 到正在听的这章能逐句高亮 | ≤ 3 秒 / ≤ 60 秒 |

比上一次提交差就不过。

### 11.3 听着考

读两页 → 锁屏听十分钟 → 打开书，位置对不对；连点十句，每句是不是从句首干净地开始、不带上一句的尾巴；睡前定时，第二天找不找得回来；戴耳机按句往回跳三次，是不是每次正好一句。

## 十二、播放器

### 12.1 引擎

| | Apple | Android |
|---|---|---|
| 播放 | `AVAudioEngine`：`AVAudioPlayerNode` 按文件分段调度（提前排好下一个文件，文件间不断档）→ 变速 → 均衡 → 压缩 → 限幅 → 输出 | Media3 ExoPlayer：播放列表（不断档）+ 自己的 `AudioProcessor` 链 |
| 变速不变调 | `AVAudioUnitTimePitch`（或同等质量的时域算法） | Sonic 处理器 |
| 后台、锁屏、车机、手表 | `MPNowPlayingInfoCenter`、`MPRemoteCommandCenter`、CarPlay 音频 App 模板 | `MediaSessionService`、Android Auto |
| 留在原处的文件、网盘上的文件 | 按范围读；先下一段再播 | 同 |

整本的时间轴 = 各文件首尾相接；对外只暴露整本的秒。跳转 = 找到文件 + 文件内偏移。

### 12.2 处理链

1. **人声增强**（开关）：高通 80 Hz；2–4 kHz 提 3 dB；压缩（比 3:1，阈值按这本书的响度定）；限幅 −1 dBTP。
2. **响度统一**：导入后后台量整本的响度（抽样量 60 秒 × 10 处即可），播放时加一个固定增益到 −18 LUFS。每本书存自己的增益。
3. **缩短停顿**（开关）：用停顿表（没有就实时检测能量）。> 0.6 秒的停顿压到 0.35 秒，两端各做 20 毫秒交叉淡化；不是删光。累计省下的时间显示给用户。和对照表的关系：时间换算永远用**原始时间**，缩短只发生在输出端。
4. **倍速**：0.5–3.0，步进 0.05；每本书记自己的。“还剩多久”= 剩余原始时长 ÷ 倍速 − 预计省下的停顿。

### 12.3 控制

| 操作 | 做什么 |
|---|---|
| 耳机 / 锁屏的下一首、上一首（耳机双击、三击发的就是这两个） | 有对照表：下一句 / 上一句。没有：+15 秒 / −15 秒。可改成章 |
| 锁屏和车机上的“书签”按钮（系统的书签命令） | **划线**：有对照表 → 给刚念完的那一句（按下时刻往前 0.8 秒所在的句子）建一条划线。没有 → 记一个书签，带前 10 秒的时间和（听写完之后补上的）文字 |
| 手表、灵动岛 | 同上，多一个划线键 |
| 书页上点一句 | 跳到这句（`spread` 档跳到这小段开头） |
| 书页上点一个词 | 暂停；查词；关掉查词后从这句开头接着念 |
| 搜索 | 命中在书里的位置 → `loc_to_time`；有字级时间就精确到词 |
| 单句重复 / A–B 重复 / 念完一句停 N 秒 | 用 `sentence_bounds`；学外语时用 |

**睡眠定时**：N 分钟 / 念完这句 / 念完这章。到点前 20 秒线性变轻；变轻时晃一下手机或按任何耳机键续 10 分钟。到点时记“定时开始的位置”；下次打开问“回到昨晚定时开始的地方？”

**高亮**：播放器每 100 毫秒报一次当前时间 → `time_to_loc` → 阅读器高亮那句、需要时翻页。在 `Extra` 里时不高亮，顶上显示“片头 / 不在书里的话”。锁屏封面下的副标题显示当前这一句的前 30 个字。

### 12.4 朗读补位

8.5 的“用朗读补上”和“录音到头了书还没完”都走同一条路：播放器把控制权交给朗读的播放器，念完交回。两个播放器共用一个进度（`Loc`）。

## 十三、同步和传文件

- **同步的**（都很小）：`SyncMap`、章节标题的修改、配对关系、用户钉的锚、每本书的播放设置（倍速、增益、三项跳过）、进度、划线和书签。
- **不同步的**：录音文件、听写稿、字级时间。
- **录音怎么到手机**：
  1. 同一个局域网里从 Mac 直接传（手机上看到“Mac 上有这本的录音 · 传过来”），可只传没听的部分；
  2. 文件在用户自己的网盘 / 家里的服务器上：边下边听，听过的章节可自动清掉；
  3. 手机上直接导入同一份文件：`audio_id` 相同，自动接上。
- 对照表的冲突：两台设备各自对齐出了不同版本 → 取算法版本高的；一样就取 `auto` 档比例高的；用户钉的锚两边取并集后重算受影响的段。

## 十六、风险和退路

| 风险 | 退路 |
|---|---|
| 手机上整本听写太慢、太费电 | 只做正在听的那章；整本等充电；或直接用 Mac 同步来的对照表 |
| 中文 `auto` 档到不了 97% | 守“不给错的时间”，放比例：多一些 `spread` |
| 背景音乐、广播剧式录音 | 整章降成 `chapter` 档 |
| 录音是另一个版本 | 认出来、说清楚，按章对或用文字版 |
| 对齐模型不支持这门语言 | 只用听写的字级时间（粗）+ 吸到停顿，阈值更严，多数句子落在 `spread` |

| 换了算法旧结果不一致 | 对照表带版本；用户钉的锚保留并当已知条件 |
| 录音文件被用户挪走了（留在原处的） | 按 `audio_id` 重新认；找不到提示重新指位置，对照表和进度都还在 |

## 十七、定了的（2026-11-12）

1. **书中间多出来的话默认照放**，片头片尾默认跳过，章间音乐默认压短。每本书可改。
2. **耳机的下一首 / 上一首默认按句跳**；没有对照表时自动退成 15 秒。划线用系统的“书签”按钮（锁屏、车机、手表上都有），不占耳机按键。
3. **没有电子书的文字版放在第 6 步**。它复用第 2、3 步的全部东西，只多一遍精听和整理；先把有电子书这条主线做准。
4. **核心不联网、不跑模型**，用作业制和各端配合；所有比较在读音上做，不在字上做。
5. **对不准就降级，不给错的精确时间**：`auto` / `spread` / `chapter` 三档。

- **手机屏幕关着才做整本**：Android 要插电且屏幕关着（`isInteractive`）；iPhone 读不到屏幕状态，用“插电且语阅不在前台”（锁屏或在用别的 App）。插上电、关屏（iPhone：进后台、电池状态变了）时，这次打开过的有声书自动接着做。原来做完附近就停，之后插电也不会再开始。
- **Android 转成文字**：用 SenseVoice-Small（FunAudioLLM，中英日韩粤，FunASR 模型许可，允许再分发、要署名），sherpa-onnx 导出的 int8 版 239 MB，用 App 已有的 onnxruntime 跑。核心 `sensevoice.rs` 做输入（和声纹共用的 fbank 改成 Hamming 窗，七帧一叠、每六帧一步，按模型自带的均值方差归一）和解码（CTC 取最大、合并、一个汉字一个词、英文按词、标点跟前一个词，每个词带时间）。App 只跑模型、每帧取最大。长录音每段最多 28 秒，在后三分之一里最安静的地方切。做完交给现成的 `audiobook_make_text_version`，接着自动对齐。界面：播放页“书架上有同一本电子书”那张卡的位置，没书时出“这本录音 · 没有电子书 · 转成文字”，进度条、第几集、还要多久；第一次要先下听写模型。
  - 实测（Mac，Python 跑模型 + 核心算输入和解码）：系统声音念的“宝玉听了这话……谁知你们都在这里。”和《傲慢与偏见》开头一句，中英文都一字不差，带标点。
