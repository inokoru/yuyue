# 反馈

反馈页、发送、离线队列和附件，SwiftUI（`apple/Yuyue/App/Feedback.swift`）和 Compose（`android/app/src/main/java/app/yuyue/feedback/Feedback.kt`）里都已做好。

这条链路是：App 把反馈发到公共的 [ntfy.sh](https://ntfy.sh)，纯后台的 Cloudflare Worker（`feedback/worker/`，无需域名）每 5 分钟检查一次，发现未处理反馈时通过 `workflow_dispatch` 唤醒中转仓库的 GitHub Actions，把它搬进**语阅仓库（公开）的 Issue**，打「反馈」标签；维护者在本机用私钥解开私密附件，处理进度再写回 Issue。不自建服务器，**表单内不收集邮箱或任何联系方式**（需要回复或私下沟通的用户，表单提供 `mailto:yuyue.app@icloud.com` 入口由用户自行发信）。

```
App ──▶ ntfy.sh ──(Worker 每 5 分钟按需唤醒)──▶ GitHub Actions ──▶ 公开 Issue（inokoru/yuyue）
                                              │  不解密            公开截图 → 公开附件仓库
                                              │                    私密附件 → 私有附件仓库（密文）
                                              ▼
                                        维护者本机：私钥解开私密附件 ──▶ 问题跟进与回写
```

## 为什么是这条路

- ntfy.sh 在中国大陆能连上。未登录时按 IP 算：每天 250 条，消息留 12 小时；附件单个最大 2 MB，总共 20 MB，只留 3 小时（2026-11 从 `https://ntfy.sh/v1/account` 查到）。
- 语阅是开源项目（GPL-3.0），反馈要公开：别人能看到问题、帮忙排查，也能看到处理进度。所以正文、类别、版本、系统**明文**发，截图默认也公开（用户可以关掉）。
- 不公开的只有：日志和其他文件、用户选了不公开的截图。这些在 App 里就用开发者的公钥封好（libsodium sealed box，`crypto_box_seal`，X25519）。**私钥只在开发者的 Mac 上**，不进 GitHub：Actions 只搬运密文，私有仓库或 Actions 出了事也解不开。
- 消息格式在 Rust core：`feedback_message` 和 `seal_feedback_file`（`core/yuyue-core/src/feedback.rs`）。编过 core 之后，Swift 是 `feedbackMessage(draft:)`，Kotlin 是 `feedbackMessage`。入参是 `FeedbackDraft`（`category` 为 `bug` / `idea` / `other`，加上正文、版本、平台、系统版本、附件的 ntfy id）。返回一段 JSON（`{"v":2,…}`），当作 ntfy 消息正文 POST 到 `https://ntfy.sh/<话题>`。空正文、超长、附件 ID 不合法都会拒绝。

## 隐私和长度

发出去的只有这几样：正文（按 Markdown 写，Issue 里照样渲染）、可选的附件，以及「附加信息」。附加信息现在是应用版本、系统版本和设备型号，表单里单独一张卡片原样列出来，默认打开，用户可以关掉；以后要多带什么，也加在这张卡片里，用户发之前都看得到。不收邮箱或联系方式，不带书、笔记，也没有能认出这台设备的信息。

- **表单上怎么说**：底部写着「正文将公开在 GitHub Issues ↗ · 日志和私密附件仅开发者可见」（Android：「内容会公开在 GitHub 上。日志和私密附件只有开发者能看到」），同时提供「需要回复或不想公开？直接发邮件 ↗」（`mailto:yuyue.app@icloud.com`），由用户自己的邮件客户端直接发信，App 不采集也不存储用户邮箱。附了截图时，多出一张「截图公开在 GitHub 上」卡片，开关默认打开，说明是「语阅是开源项目，截图和文字一起公开，别人也能帮忙查。发之前看一眼截图里有没有隐私」。关掉后截图照样发出，只是和日志一样密封，只有开发者能看到。
- **附件**：截图、日志、打不开的书都可以，最多 3 个。图片先缩到长边不超过 1600 像素，再用像素重新编成 1 MB 以内的 JPEG，原图里的位置、相机、时间都不会带出去。
  - 公开的截图：JPEG 原样 PUT 成一条 ntfy 附件消息（正文 `v2shot`）。中转只收 JPEG，推到公开仓库 `inokoru/yuyue-feedback-assets` 的 `<ntfy-id>/<n>.jpg`，贴进 Issue。
  - 其他附件（不是图片的文件，或者不公开的截图）：用 `seal_feedback_file` 连同文件名一起密封（明文是 `YYF1`、名字长度、名字、文件内容），PUT 成一条 ntfy 附件消息（正文 `v1file`）。每个最多 1.5 MB。中转原样提交到私有仓库的 `feedback-files/<ntfy-id>/<n>.sealed`；Issue 里只写「附件 n（大小，只有开发者能看到）」，连文件名都不露。
  - 拿到的消息 id 写进 `FeedbackDraft.files`。附件必须当场有网才能发：传失败了什么都不算，表单内容原样保留。原因是 ntfy 的附件只留 3 小时，放进离线队列等不了。
- **书和日志永远不公开**：书有版权，日志里可能有路径和用户名。
- **不收集邮箱**：App 表单不设邮箱输入框，公开 Issue 不存任何加密联系方式；希望私下沟通或收到邮件回复的用户，通过 `mailto:yuyue.app@icloud.com` 主动发信。
- **长度**：正文最多 800 字。整条消息不超过 ntfy 的 4096 字节。
- **App 里的限制**：不限条数，也不显示剩几条。只有真发不出去才提示：没网，或者 ntfy.sh 回 429（这个 IP 今天的额度用完，同一个运营商出口的人共用）。这两种情况消息先存在本机，之后自动补发，最多存 10 条。
- **不经过 Google**：请求都带 `X-Firebase: no`，ntfy.sh 不会再把消息转推给 Google 的 FCM。
- **防刷**：话题打包在 App 里，谁都能往里发。中转会跳过格式不对的、以及最近 24 小时内已有相同正文的反馈；每次最多开 `MAX_ISSUES` 个 Issue（默认 10），多的留到下一次；公开附件只收 JPEG；正文里的 HTML 注释和 `@某人` 会被转义，不会通知到别人。真被刷了，删掉那些 Issue，换一个话题，App 发版时带上新话题。

## 界面

摆法：

每个平台只有两处入口，读书的地方不放，不弹窗，不浮在内容上：

- 原有按钮一个都不动，只多加一个反馈图标。早期图标用主题色，稳定后变回普通颜色。
- 手机（iPhone / iPad / Android）：书架右上角「导入」「选择」前面多一个反馈图标，只在书架。「我的」里还有一行「反馈」。
- Mac：侧栏底部「还没开同步」那一行的右边，依次是设置图标和反馈图标。「帮助 › 给语阅反馈…」也能打开。
- 表单：手机上是从下面升起的 sheet（Android 是整页），Mac 上是从窗口顶上落下的 sheet。内容依次是类别、正文、「截图公开在 GitHub 上」（附了截图才出现，默认打开）、附加信息和直邮入口；没写字时发送按钮是灰的。输入框底部一行是「附件」按钮、「Markdown」提示和字数。附件以缩略图显示在框里（不是图片的显示文件图标和扩展名），每个右上角有 ×。手机上点「附件」可以选照片或文件；Mac 上可以选文件，也可以直接把文件拖进输入框。

写起来顺手的几处：
- 打开表单后光标直接在输入框里。
- 草稿自动保存：写到一半关掉，下次打开还在，附件也在（文字存在偏好设置里，附件存在 App 自己的目录下）；发出去或者进了离线队列才清掉。
- 输入框跟着内容变高，不在小框里滚动。
- 字数平时不显示，写到 600 字才出现。
- 截图由用户自己截，截哪里、截多少用户定。Mac 上点「截图」：表单收起，屏幕下方浮出一条小条（不抢焦点，在所有窗口之上）。用户照常去翻书、开设置，到了要截的界面再点小条上的「截图」，出现系统自己的十字光标（`screencapture -i`，拖选区域，空格换成整个窗口）。截完表单自动回来，图片已在附件里；写的内容靠草稿保住。十字光标里按 Esc 回到小条，点「回到反馈」不截直接回去。第一次可能要允许「屏幕录制」。

## 限制

- ntfy.sh 每个 IP 每天 250 条，消息留 12 小时，附件只留 3 小时。工作流停太久，中间的反馈会丢。如果停了 3 小时以上，附件会先丢，Issue 里会写「附件没取到」。
- 公开的截图一旦推上去，就留在公开仓库的历史里。用户事后要求删，得改写 `inokoru/yuyue-feedback-assets` 的历史（或者删库重建），所以表单上把「公开」说在前面。
- ntfy.sh 只有一台服务器，官方说法是「尽力而为」。要是长期不稳，可以买 Supporter（每月 5 美元：每天 2500 条，附件 25 MB，还能保留话题名），或者自己搭一个 ntfy。
- 正文上限是为了塞进 ntfy 的大约 4096 字节。中文按 800 字留了余量。
- 公开构建默认没有话题和公钥。这两项在本地配置文件里，不进仓库。
