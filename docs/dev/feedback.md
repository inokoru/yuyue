# 反馈

反馈页、发送、离线队列和附件，SwiftUI（`apple/Yuyue/App/Feedback.swift`）、Compose（`android/app/src/main/java/app/yuyue/feedback/Feedback.kt`）和 WinUI（`windows/Yuyue/Core/UpdateAndFeedbackService.cs`）里都已做好。

这条链路是：App 把反馈发到公共的 [ntfy.sh](https://ntfy.sh)，纯后台的 Cloudflare Worker（`feedback/worker/`，无需域名）每 5 分钟检查一次，发现未处理反馈时通过 `workflow_dispatch` 唤醒中转仓库的 GitHub Actions，把它搬进**语阅仓库（公开）的 Issue**，打「反馈」标签；所有附件（截图和样本文件）推到公开附件仓库 `inokoru/yuyue-feedback-assets`，方便社区一起排查与贡献代码。不自建服务器，**表单内不收集邮箱或任何联系方式**（需要回复或不想公开内容的用户，表单提供 `mailto:yuyue.app@icloud.com` 入口由用户自行发信）。

```
App ──▶ ntfy.sh ──(Worker 每 5 分钟按需唤醒)──▶ GitHub Actions ──▶ 公开 Issue（inokoru/yuyue）
                                                                   截图/文件附件 → 公开附件仓库
                                                                   （inokoru/yuyue-feedback-assets）
```

## 为什么是这条路

- ntfy.sh 在中国大陆能连上。未登录时按 IP 算：每天 250 条，消息留 12 小时；附件单个最大 2 MB，总共 20 MB，只留 3 小时（2026-11 从 `https://ntfy.sh/v1/account` 查到）。
- 语阅是开源项目（GPL-3.0），反馈和附件都公开：任何看到 Issue 的人都能拿到复现截图或样本文件帮忙查问题、提 PR，也能看到处理进度。不想公开的内容或完整版权书，表单直接引导发邮件。
- 消息格式在 Rust core：`feedback_message`（`core/yuyue-core/src/feedback.rs`）。编过 core 之后，Swift 是 `feedbackMessage(draft:)`，Kotlin 是 `feedbackMessage`，C# 是 `YuyueCoreMethods.FeedbackMessage`。入参是 `FeedbackDraft`（`category` 为 `bug` / `idea` / `other`，必填 `title`（最多 60 字）、必填 `text`（最多 800 字），加上版本、平台、系统版本、附件的 ntfy id）。返回一段 JSON（`{"v":2,…}`），当作 ntfy 消息正文 POST 到 `https://ntfy.sh/<话题>`。空标题、空正文、超长、附件 ID 不合法都会拒绝。
- **标题绝不截断**：表单单独提供单行「标题」输入框并硬限制在 60 字以内，中转脚本原样生成 `[类别] <标题>`，避免截断曲解用户意思。对于已发布的旧版客户端（0.1.0 / 0.1.1，无 `title` 字段），中转保留兜底逻辑（优先保留首行/首句，上限 120 字）并兼容其 `v1file` 密封附件。

## 隐私和长度

发出去的只有这几样：标题、正文（按 Markdown 写，Issue 里照样渲染）、可选的附件，以及「附加信息」。附加信息现在是应用版本、系统版本和设备型号，表单里单独一张卡片原样列出来，默认打开，用户可以关掉；以后要多带什么，也加在这张卡片里，用户发之前都看得到。不收邮箱或联系方式，不带书、笔记，也没有能认出这台设备的信息。

- **表单上怎么说**：底部明示「正文和附件将公开在 GitHub Issues ↗ · 请勿上传隐私或版权书」（Android：「正文和附件都会公开在 GitHub 上，请勿上传隐私或完整版权书」），同时提供「需要回复或不想公开？直接发邮件 ↗」（`mailto:yuyue.app@icloud.com`），由用户自己的邮件客户端直接发信，App 不采集也不存储用户邮箱。
- **附件**：截图、打不开的样本文件或日志都可以，最多 3 个。图片先缩到长边不超过 1600 像素，再用像素重新编成 1 MB 以内的 JPEG，原图里的位置、相机、时间等 EXIF 元数据都不会带出去；非图片文件每个最多 1.5 MB。
  - 截图：JPEG 原样 PUT 成一条 ntfy 附件消息（`Filename: shot-<n>.jpg`，`X-Message: v2shot`）。中转校验为 JPEG 后推到公开仓库 `inokoru/yuyue-feedback-assets` 的 `<ntfy-id>/<n>.jpg`，在 Issue 里直接贴图 `![截图 n](...)`。
  - 其他文件：原样 PUT 成一条 ntfy 附件消息（ASCII 安全的 `Filename: file-<n><ext>`，`X-Message: v2file <percent-encoded-name>`）。中转推到公开仓库 `inokoru/yuyue-feedback-assets` 的 `<ntfy-id>/<n><ext>`，在 Issue 里展示查看与直接下载链接，方便社区贡献者直接下载复现。
  - 拿到的消息 id 写进 `FeedbackDraft.files`。附件必须当场有网才能发：传失败了什么都不算，表单内容原样保留。原因是 ntfy 的附件只留 3 小时，放进离线队列等不了。
- **不收集邮箱**：App 表单不设邮箱输入框，公开 Issue 不存任何联系方式；希望私下沟通或收到邮件回复的用户，通过 `mailto:yuyue.app@icloud.com` 主动发信。
- **长度**：标题最多 60 字，正文最多 800 字。整条消息不超过 ntfy 的 4096 字节。
- **App 里的限制**：不限条数，也不显示剩几条。只有真发不出去才提示：没网，或者 ntfy.sh 回 429（这个 IP 今天的额度用完，同一个运营商出口的人共用）。这两种情况消息先存在本机，之后自动补发，最多存 10 条。
- **不经过 Google**：请求都带 `X-Firebase: no`，ntfy.sh 不会再把消息转推给 Google 的 FCM。
- **防刷**：话题打包在 App 里，谁都能往里发。中转会跳过格式不对的、以及最近 24 小时内已有相同正文的反馈；每次最多开 `MAX_ISSUES` 个 Issue（默认 10），多的留到下一次；正文里的 HTML 注释和 `@某人` 会被转义，不会通知到别人；附件文件名会转义 Markdown 特殊字符并做安全扩展名过滤。真被刷了，删掉那些 Issue，换一个话题，App 发版时带上新话题。

## 界面

摆法：

每个平台只有两处入口，读书的地方不放，不弹窗，不浮在内容上：

- 原有按钮一个都不动，只多加一个反馈图标。早期图标用主题色，稳定后变回普通颜色。
- 手机（iPhone / iPad / Android）：书架右上角「导入」「选择」前面多一个反馈图标，只在书架。「我的」里还有一行「反馈」。
- Mac：侧栏底部「还没开同步」那一行的右边，依次是设置图标和反馈图标。「帮助 › 给语阅反馈…」也能打开。
- 表单：手机上是从下面升起的 sheet（Android 是整页），Mac 上是从窗口顶上落下的 sheet。内容依次是类别、标题（单行，限 60 字）、正文（限 800 字）、附加信息和直邮入口；标题或正文任一为空时发送按钮是灰的。正文框底部一行是「附件」按钮、「Markdown」提示和字数。附件以缩略图显示在框里（不是图片的显示文件图标和扩展名），每个右上角有 ×。手机上点「附件」可以选照片或文件；Mac 上可以选文件，也可以直接把文件拖进输入框。

写起来顺手的几处：
- 打开表单后光标直接在标题框（已有标题草稿时直达正文框），按回车自动切到正文框。
- 草稿自动保存：写到一半关掉，下次打开还在，标题、正文和附件都在；发出去或者进了离线队列才清掉。
- 正文框跟着内容变高，不在小框里滚动。
- 字数平时不显示，标题写到 45 字、正文写到 600 字才出现。
- 截图由用户自己截，截哪里、截多少用户定。Mac 上点「截图」：表单收起，屏幕下方浮出一条小条（不抢焦点，在所有窗口之上）。用户照常去翻书、开设置，到了要截的界面再点小条上的「截图」，出现系统自己的十字光标（`screencapture -i`，拖选区域，空格换成整个窗口）。截完表单自动回来，图片已在附件里；写的内容靠草稿保住。十字光标里按 Esc 回到小条，点 `×` 直接关闭截图条。第一次可能要允许「屏幕录制」。

## 限制

- ntfy.sh 每个 IP 每天 250 条，消息留 12 小时，附件只留 3 小时。工作流停太久，中间的反馈会丢。如果停了 3 小时以上，附件会先丢，Issue 里会写「附件没取到」。
- 公开附件一旦推上去，就留在公开仓库的历史里。用户事后要求删，得改写 `inokoru/yuyue-feedback-assets` 的历史（或者删库重建），所以表单上把「正文和附件公开，请勿上传隐私或版权书」说在前面。
- ntfy.sh 只有一台服务器，官方说法是「尽力而为」。要是长期不稳，可以买 Supporter（每月 5 美元：每天 2500 条，附件 25 MB，还能保留话题名），或者自己搭一个 ntfy。
- 标题（60 字）与正文（800 字）上限是为了塞进 ntfy 的大约 4096 字节并保证 GitHub Issue 标题永不截断。
- 公开构建默认没有话题配置。话题写在本地配置文件里，不进仓库。
